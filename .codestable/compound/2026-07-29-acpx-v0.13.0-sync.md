## Adapter Major 兼容决策

Codex adapter 从 `^0.0.44` 更新到 `^1.1.5`，属于默认命令的 major 变化；Claude 同时从
`^0.37.0` 更新到 `^0.60.0`。本次仅替换 ACP stdio adapter 包范围，不改变 Agent 名称、MCP 工具、
Facade snapshot、runtime session schema、权限模型或 Workspace owner。发布前必须用本机登录态分别
完成 Codex/Claude 创建、发送、等待、销毁，并确认递归身份注入仍成立；任一真实 E2E 失败即停止收口。

首轮独立审查发现 runtime session record 保存完整 `agentCommand`，直接更新 registry 会使升级前的
持久 Agent 因命令字符串不同而无法恢复。修复增加显式旧内置命令迁移表：只有旧、新命令均解析为
同一内置 Agent 时才复用已有后端 session，并立即把 record 保存为当前命令；未知自定义命令和跨
Agent 命令仍不兼容。Codex `^0.0.44` record 在 `requireExistingSession` 下恢复的回归先失败，再通过。

## 遗留风险

- 本机没有可用的 Pool/ZeroClaw CLI/ACP 环境，live probe 均为 unavailable；本轮只声明 registry
  与通用 ACP client/runtime 支持，不声明这两个 Agent 已通过实机任务。
- Claude adapter `0.60.0` 不支持 `session/close` 时，`discardSession: true` 会返回明确的可选能力错误；
  普通 destroy 已实测成功。这是 adapter 能力边界，不改变标准 Agent 生命周期。
- 旧命令迁移有 manager/store 结构回归，但未在本机保留一个由旧 adapter 真正创建的后端 session，
  再由新版 adapter 执行跨版本 load/resume；真实后端的跨版本 session 格式仍由 adapter 自身兼容性决定。
- Windows package-exec 分支仅有现有 Windows 命令包装回归，本机未执行 Windows 实机 E2E。
